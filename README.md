# NGPanel

Панель для домашнего IPv4-шлюза Xray на Ubuntu 24.04 amd64. Интерфейс компактный, тёмная тема основная. Авторизации пока нет: панель предназначена для доверенной домашней сети.

## Установка панели на чистую Ubuntu

На чистой Ubuntu 24.04 amd64 выполните:

```sh
curl -fsSL https://raw.githubusercontent.com/Mendex777/NextGateway_0.2/master/install.sh | sudo bash
```

Загрузчик скачивает последний стабильный релиз, проверяет SHA-256 архива и установщика по API GitHub, затем контрольные суммы файлов по манифесту. Устанавливается готовый бинарник: Git, Go и сборка на ВМ не нужны. Панель запускается автоматически на `http://<IPv4-ВМ>:8080` и добавляется в автозапуск. Установщик также устанавливает Xray, компоненты шлюза и geo-базы, определяет сеть ВМ, применяет начальную конфигурацию и запускает шлюз. После установки добавьте подписку или ноду, настройте правила и нажмите «Применить».

Если `curl` отсутствует: `sudo apt-get update && sudo apt-get install -y curl`, затем повторите команду. Для другого порта передайте `sudo env NG_LISTEN=0.0.0.0:8081 bash` вместо `sudo bash`.

Для сборки из исходников клонируйте репозиторий, выполните `npm ci --prefix frontend` и `npm run build --prefix frontend` (Node.js 22.12+), затем `sudo sh deploy/install-panel.sh` из его каталога. Существующая база при повторной установке из исходников сохраняется. Чужую службу xray.service установщик не заменяет.

Интерфейс LAN, IPv4 ВМ, подсеть и текущий шлюз определяются автоматически по сети ВМ. При первой настройке DNS берётся из системных upstream-резолверов ВМ; локальные stub-адреса и адрес самой ВМ исключаются. Сохранённые параметры можно изменить на странице «DNS и шлюз». Порт панели открывается на всех IPv4-интерфейсах; не публикуйте его в интернет.

Первый вход открывает обычный дашборд без мастера настройки. Повторный запуск команды обновляет панель или проверяет текущую версию, восстанавливает недостающие компоненты и сохраняет базу, порт панели, сетевые параметры и применённую конфигурацию. Перед заменой создаётся резервная копия в `/var/tmp/ngpanel-before-install.*`. При ошибке возвращаются предыдущие файлы панели, база и службы. Установщик не заменяет чужую службу Xray и не выполняет понижение версии.

Для настройки вручную:

1. Откройте «Главная» и установите официальный Xray (проверяется SHA-256 релиза).
2. В «DNS и шлюз» установите компоненты шлюза.
3. В «Маршрутизация» обновите geo-базы, если используете geosite/geoip.
4. Восстановите бекап или добавьте подписки/подключения и правила вручную.
5. Настройте выход ВМ через роутер и подтвердите доступность панели в течение 120 секунд.
6. Настройте DNS, включите перехват и примените конфигурацию.
7. Задайте устройствам шлюз и DNS — IPv4 этой ВМ, показанный в панели.

## Бекап

Окно «Бэкап» на дашборде скачивает JSON с контрольной суммой. В него входят все таблицы SQLite: подписки с URL и HTTP-заголовками, подключения с ключами, выбранный VPN, правила и порядок, устройства и настройки панели. Файл содержит секреты: храните приватно и не добавляйте в Git.

Восстановление заменяет сохранённые данные одной транзакцией; неверный формат, контрольная сумма или связи данных отклоняются. Дождитесь завершения обновления подписок и проверок подключений. Работающий Xray не изменяется автоматически: после восстановления нажмите «Применить изменения». Xray, geo-базы, настройки сети Ubuntu и системные файлы в JSON не входят: на новой ВМ установите их по шагам выше.

## Дашборд

Главная использует раскладку дашборда 3x-ui: CPU, память, swap, диск, трафик интерфейса, сокеты TCP/UDP и время работы. Показатели обновляются раз в 2 секунды; история содержит последние 72 серверных измерения и сохраняется при обновлении вкладки. Трафик и сокеты относятся ко всей ВМ, а окно «Метрики Xray» показывает память, потоки, PID и время работы процесса Xray.

Логи Xray и панели, применённая конфигурация и бекап открываются в модальных окнах. Графики используют оригинальный компонент Sparkline/uPlot 3x-ui (сглаживание, затухающая заливка, пунктирная сетка, линии среднего и текущего значения, всплывающие значения). Журналы загружаются ограниченным системным заданием; автообновление запрашивает их раз в 10 секунд. Конфигурация доступна только для чтения, скачивания и копирования. Снимок хранится с доступом root и группы ngpanel. Кнопка настройки открывает компоненты шлюза и мастер установки; версия панели открывает обновления и откат.

При импорте бекапа можно сохранить сетевые параметры текущей ВМ (интерфейс, IPv4, подсеть и роутер). Старые JSON-бекапы совместимы; восстановление не перезапускает Xray до применения изменений.

## Возможности

- SQLite; независимый от Xray веб-интерфейс и отдельные службы systemd.
- Подписки: текст/Base64 VLESS и Hysteria 2, HTTP-заголовки, автообновление, информация о трафике/сроке, раскрываемые группы подключений.
- Параллельные проверки подключений: до 8 TCP-проверок и пакеты до 16 HTTPS-проверок через общий тестовый Xray. Задержка измеряется через Google generate_204, выходной IP и страна — отдельным запросом через VPN. Поддерживается отмена.
- Правила domain/geosite, IPv4/geoip и устройств, прямой/общий VPN/конкретное подключение/блокировка. Порядок сверху вниз, drag and drop и стрелки, добавление/изменение в модальных окнах.
- Поиск geo-категорий и содержимого, компактные раскрываемые списки значений.
- Устройства из таблицы соседей, автоматические имена через DNS/mDNS/производителя MAC, ручные имена.
- DNS: прямой, через выбранный VPN или по общим доменным правилам; UDP IPv4/DoH, отдельные резервные списки. Bootstrap напрямую, общий кеш; правила устройств/IP не выбирают DNS. A/AAAA следуют политике, другие типы пересылаются на Bootstrap напрямую. DoT пока отсутствует.
- Диагностика сохранённого маршрута и DNS, предварительный результат при недостающем IPv4/источнике; это расчёт конфигурации, а не наблюдение трафика.
- TPROXY/nftables, восстановление после запуска ОС; остановленный VPN не заменяется прямым выходом. Применение конфигурации перезапускает Xray и может прервать соединения.

## Разработка и проверки

```sh
go test ./...
go vet ./...
go build .
```

`deploy/test-gateway.py` и другие интеграционные проверки запускайте только на тестовой ВМ: они могут перезапускать Xray и временно изменять сеть. Системные задания выполняет root-компонент с фиксированным списком действий; веб-панель работает без root.

Keenetic/Entware, IPv6, пользовательские входящие и группы автоматического переключения VPN отложены.

## Обновление панели

На странице «Главная» доступны проверка релиза, установка и откат панели (блок «Управление и обновление»). Источник — публичные GitHub Releases `Mendex777/NextGateway_0.2`, архив `ngpanel-linux-amd64.tar.gz`. Токен не требуется. Ветка Git сама по себе не является обновлением: нужно опубликовать релиз.

Интерфейс v0.2.18: боковая навигация, обзор компонентов, общий индикатор неприменённых изменений, компактные подписки и группы. Участники группы выбираются с поиском, фильтром по подписке и метками выбранных подключений; фильтры не снимают выбор. Правила включаются переключателями без перезагрузки страницы; для изменения работающего Xray требуется применить конфигурацию. Дополнительные действия с подключением доступны в меню «⋯». На телефоне навигация сворачивается, подключения отображаются компактными строками. Фильтр и раскрытые группы сохраняются в браузере. Задержка HTTPS и время последней проверки показываются отдельно; это результат проверки, а не постоянная гарантия доступности. Стили находятся в `ui.css` и встраиваются в бинарник, внешние CDN и сборщик frontend не требуются.

Архив проверяется по SHA-256 из API GitHub; содержимое — по манифесту. Перед заменой файлов панель останавливается, её база сохраняется через SQLite backup. Xray не останавливается. После запуска проверяются HTTP health, версия и доступность базы; при ошибке возвращаются предыдущие файлы и база. Ручной откат также возвращает базу к состоянию до обновления; перед ним автоматически сохраняется ещё одна копия в `/var/lib/ngpanel/updates/`. Системные unit-файлы updater устанавливаются первоначальным установщиком.

Для подготовки релиза на Ubuntu amd64:

```sh
sh deploy/build-release.sh "$(cat VERSION)"
```

Загрузите `dist/ngpanel-linux-amd64.tar.gz` в обычный GitHub Release с тегом из `VERSION`. Черновики и prerelease не предлагаются для автоматического обновления. Имя и SHA-256 артефакта обязательны. `python3 deploy/test-panel-update.py` проверяет отказ повреждённого архива, запрет выхода за каталог и откат файлов/базы при неуспешном запуске.

Сохранение параметров LAN не меняет сеть Ubuntu. Применение выхода через роутер сохраняет DHCP и требует подтверждения доступности панели в течение 120 секунд; иначе Netplan откатывается. Перехват применяйте отдельно после подтверждения. После перезагрузки и при откате используется применённый профиль сети, а не новые неприменённые настройки. Сетевой профиль входит в бекап настроек панели; после переноса на другую ВМ его нужно проверить перед применением.

Неподтверждённая настройка Netplan также восстанавливается после перезагрузки до запуска панели и шлюза. Служба восстановления устанавливается при первом изменении выхода ВМ.

Группы VPN создаются в «Подписки и подключения» → «Создать группу». Это независимые именованные выходы: до 16 групп, по 2–8 явно выбранных участников. Группу можно назначить правилу, устройству или маршруту по умолчанию, после чего применить конфигурацию. Само создание группы не меняет маршруты; «Выбранный VPN» остаётся конкретным вручную выбранным узлом и автоматически в группы не добавляется. У каждой используемой группы свой leastPing-балансер и отдельный набор выходов. Общий observatory проверяет HTTPS через узлы с минимальным интервалом используемых групп (10–600 секунд); URL Google generate_204, таймаут ядра 5 секунд. Новые соединения идут через доступный узел с минимальной задержкой; существующие TCP-потоки остаются на своём узле, при отказе сервера приложения переподключаются. Автовыбор не перезапускает Xray и работает без браузера. При недоступности всей группы трафик блокируется. В DNS-режиме «По правилам» общее доменное правило группы и маршрут по умолчанию используют ту же группу; режим «Через VPN» использует вручную выбранный VPN. Группы включены в бекап, а используемую группу нельзя удалить. Предыдущая общая группа переносится как независимая без автоматического назначения правилам.

Режим группы «Самый быстрый» использует нативный leastPing. «По порогу задержки» удерживает текущий узел, пока его HTTPS-задержка не превысит порог (50–60000 мс) заданное число отдельных проверок подряд (1–10); переключения по задержке ограничены паузой (0–3600 с). «Только при отказе» не реагирует на задержку. При отказе текущего узла переключение выполняется после неудачной проверки без ожидания паузы. Если все доступные узлы выше порога, допускается переход на более быстрый; если улучшения нет, текущий сохраняется. При отсутствии свежих доступных результатов трафик блокируется. Два последних режима обслуживает служба панели через loopback API Xray (ObservatoryService и RoutingService); панель должна работать. Для новых соединений устанавливается override балансера; существующие TCP-потоки не перезапускаются. После перезапуска панели состояние выбора восстанавливается из текущих измерений. Настройки хранятся в бекапе и применяются отдельным применением конфигурации; работающий контроллер читает снимок применённых настроек, а не ещё не применённые правки. В таблице группы показываются HTTPS-задержка, доступность и время проверки участников; выбранный выход виден также в заголовке свёрнутой группы.


Живые соединения остаются на ранее выбранном выходе. При отказе самого сервера они не переносятся на другой сервер и могут оборваться; новые соединения пойдут через рабочий узел. Изменение состава группы требует применения конфигурации с перезапуском ядра. На странице показывается выход для новых соединений из RoutingService API, доступного только на 127.0.0.1:10085. Группа входит в бекап; обновление подписки сохраняет используемые ею подключения.

Проверка балансера настоящим Xray: `python3 deploy/test-balance-live.py`. Тест использует только отдельные loopback VLESS/HTTP-серверы, проверяет смену задержки с сохранением живого потока, отказ узла, блокировку всех недоступных узлов и восстановление при неизменном PID ядра. `NG_XRAY_INTEGRATION=1 go test ./...` дополнительно проверяет сгенерированный панелью конфиг в Xray и ограничения root-контроллера.

В v0.2.17 маршрут по умолчанию сохраняется автоматически, применение вынесено в закреплённое уведомление, действия правил собраны в меню, перетаскивание работает без перезагрузки с плавным перемещением строк.

В v0.2.19 навигация и маршрутизация оформлены по образцу 3x-ui: тёмная палитра, значки Ant Design, сворачиваемое и закрепляемое меню, поиск страниц (Ctrl+K), вкладки базовых соединений, правил и проверки маршрута. Верхний блок показывает состояние конфигурации и позволяет применить сохранённые изменения к Xray. Правила сохраняются без автоматического применения; проверка маршрута использует сохранённые правила. Порядок можно менять перетаскиванием или через меню строки. Дизайн проверен на узком экране. Лицензия значков находится в THIRD_PARTY_NOTICES.txt и включена в шаблон страницы.

## Интерфейс и лицензия

React 19, TypeScript, Ant Design 6 и Vite; сервер Go/Gin. Готовые ресурсы интерфейса встроены в бинарник: Node.js на установленной ВМ не требуется. SQLite, системные операции и формат бекапа сохранены.

Оформление и организация интерфейса основаны на [3x-ui](https://github.com/MHSanaei/3x-ui), GPL-3.0. Проект распространяется по GPL-3.0; текст лицензии находится в LICENSE.

### Бекап и шаблоны маршрутизации

«Бэкап и восстановление» на главной сохраняет все таблицы настроек: подписки и ключи подключений, группы, устройства, правила, DNS, параметры шлюза и состояния включения. JSON также содержит снимок последней применённой конфигурации Xray (`applied_xray_config`) для справки. Восстановление возвращает сохранённые настройки; запуск выполняется отдельно кнопкой «Применить». Исполняемые файлы Xray, geo-базы, журналы и настройки браузера в этот файл не входят.

На странице маршрутизации «Экспорт правил» создаёт переносимый JSON `ngpanel-routing` версии 1. Он сохраняет порядок и состояние правил, ограничения IP устройств и маршрут по умолчанию, но не содержит URI узлов и адресов подписок. Direct, выбранный VPN и блокировка имеют стандартные значения; остальные исходящие представлены именованными ссылками и при импорте сопоставляются с локальными узлами или группами. IP устройств проверяются и редактируются перед импортом. Правила можно добавить, заменить или пропустить по исходящему; маршрут по умолчанию переносится только по явному выбору.

Для загрузки с GitHub укажите HTTPS-ссылку на файл (`github.com/.../blob/...` или `raw.githubusercontent.com`, также поддерживается `gist.githubusercontent.com`). Пример формата: [docs/routing-template-example.json](docs/routing-template-example.json). Обновление шаблона по ссылке вручную: повторная загрузка не синхронизирует правила автоматически.
