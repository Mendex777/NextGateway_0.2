# Проверка готовности шлюза

Главная получает `/api/service-health`: готовый отчёт, без запуска системных команд из HTTP-запроса. `ngpanel-health.service` обновляет его раз в 10 секунд. При отсутствии отчёта или возрасте больше 45 секунд готовность неизвестна, старые зелёные статусы не сохраняются.

Проверяются Xray и версия, JSON и хеш применённого конфига, адрес/маска/интерфейс и основной роутер, точное содержимое таблицы `inet ngpanel`, policy routing, ip_forward/rp_filter, TCP/UDP-входы 7895/1053, DNS-запрос через Xray, используемые geo-базы и автозапуск. Эти проверки не подтверждают доступность каждого VPN: она отдельно отображается на карте.

Эталон nftables `/etc/ngpanel/gateway-baseline.json` сохраняется после успешного применения правил. При установке на существующую ВМ он создаётся из сохранённого `gateway.nft` в отдельном сетевом namespace. Рабочая таблица никогда не принимается за эталон автоматически. При сравнении игнорируются только метаданные, handles и меняющиеся значения счётчиков; порядок правил и определения цепочек сравниваются.

Проверка `xray run -test` выполняется с UID/GID ngxray, кешируется до минуты, повторяется при изменении конфигурации, прав, владельца, версии ядра или метаданных баз. DNS-запрос example.com кешируется на 30 секунд. Это ограничивает нагрузку независимо от числа вкладок браузера. Geo-базы проверяются на наличие, а используемые категории — загрузкой конфигурации ядром; дата файла не является проверкой актуальности опубликованной базы.

Сборщик только читает состояние. Права NET_ADMIN требуются для чтения nftables, CHOWN — для передачи отчёта группе ngpanel, SETUID/SETGID — для проверки конфигурации от имени ngxray. Веб-процесс этих прав не получает. Применение правил и исправление сбоев остаются отдельными действиями.

Установка сборщика: `sudo python3 /opt/ngpanel/control.py health-install`. Однократная диагностика: `sudo /opt/ngpanel/ngpanel --check-health`. Отчёт: `/run/ngpanel-health/health.json` (root:ngpanel, 0640). В нём нет адресов VPN-серверов, ключей, UUID и полного конфига.

Логика сбоев проверяется Go-тестами на подставных данных; браузерные сценарии выполняются на копии базы и тестовом отчёте, без отключения рабочего шлюза.

## Обновления компонентов

В едином блоке главной показаны NGPanel, Xray, geo-базы и короткие индикаторы готовности. Сбои видны без раскрытия; технические сведения открываются по нажатию. `/api/component-updates` отдаёт кеш сведений о последних стабильных официальных выпусках. Веб-процесс проверяет их в фоне раз в 6 часов и по кнопке, а не при каждом HTTP-запросе. Кеш хранится в доступной ngpanel папке `db/component-updates.json`. При ошибке проверки или устаревании сведений обновление не объявляется доступным.

Для NGPanel и Xray сравниваются версии; для geosite/geoip — SHA-256 установленных файлов и обоих опубликованных assets. Обновление выполняется только по отдельному нажатию пользователя. Обновление панели использует существующий проверенный установщик релизов, geo-базы — существующую проверку SHA-256 и совместимости сохранённых правил.

Действие `xray-update` атомарно ставит фиксированное задание установщику. Новый официальный бинарник проверяется по SHA-256, версии и совместимости с текущим конфигом под ngxray до остановки службы. Затем бинарник заменяется, прежнее состояние службы сохраняется. При неудачном запуске возвращается предыдущий бинарник. Файлы конфигурации, правила сети и параметры ускорения не меняются. Во время обновления работающего ядра соединения прерываются, интерфейс предупреждает об этом перед запуском.
